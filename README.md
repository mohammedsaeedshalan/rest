# نظام إدارة المطعم

نظام ويب لإدارة عمليات المطعم، مبني باستخدام Flask وSQLAlchemy، ويدعم المبيعات والمشتريات والمخزون والعملاء والموردين والعاملين والرواتب والمصروفات والتقارير.

## المميزات

- لوحة تحكم بإحصائيات المبيعات والمشتريات والمخزون.
- لوحة مكاسب تحسب:

  `صافي المكاسب = المبيعات - المشتريات - رواتب العاملين - المصروفات`

- نقطة بيع وإصدار فواتير.
- إدارة الأصناف والكميات والحد الأدنى للمخزون.
- إدارة العملاء والموردين والأرصدة.
- تسجيل دفعات العملاء والموردين.
- إدارة العاملين وتسجيل دفعات الرواتب.
- تسجيل المصروفات اليومية مع التصنيف وطريقة الدفع.
- تقارير المبيعات والمشتريات والعملاء والموردين والرواتب والمصروفات.
- طباعة التقارير والمصروفات اليومية.
- صلاحيات المستخدمين: مدير، مشرف، مستخدم.
- دعم SQLite محليًا وPostgreSQL على Render.

## المتطلبات

- Python 3.10 أو أحدث.
- متصفح ويب حديث.

## التشغيل محليًا على Windows

افتح PowerShell داخل مجلد المشروع ثم نفّذ:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py
```

بعد ذلك افتح:

```text
http://localhost:5000
```

يمكن أيضًا تشغيل النظام بالنقر على ملف `run.bat`.

### بيانات الدخول الافتراضية

- اسم المستخدم: `admin`
- كلمة المرور: `admin123`

غيّر كلمة المرور الافتراضية بعد أول تسجيل دخول.

## التشغيل عبر Gunicorn

يُستخدم Gunicorn في بيئات Linux وRender:

```bash
gunicorn app:app --bind 0.0.0.0:$PORT
```

## النشر على Render

المشروع يحتوي على ملف `render.yaml` جاهز لإنشاء Web Service وقاعدة PostgreSQL.

1. ارفع المشروع إلى مستودع GitHub.
2. افتح [Render](https://render.com) وسجّل الدخول.
3. اختر **New > Blueprint**.
4. اختر مستودع GitHub الذي يحتوي على المشروع.
5. وافق على إعدادات `render.yaml` ثم اضغط **Apply**.
6. انتظر اكتمال Build وDeploy.
7. افتح الرابط الذي يوفره Render.

يستخدم Render الإعدادات التالية تلقائيًا:

- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn app:app --bind 0.0.0.0:$PORT`
- `SECRET_KEY`: يتم توليده تلقائيًا.
- `DATABASE_URL`: يتم ربطه بقاعدة PostgreSQL التي ينشئها Render.

> لا تستخدم SQLite لتخزين بيانات الإنتاج على Render، لأن نظام الملفات في الخدمة قد لا يكون دائمًا. استخدم PostgreSQL المرفق في `render.yaml`.

## المتغيرات البيئية

| المتغير | الاستخدام | مطلوب في Render |
| --- | --- | --- |
| `SECRET_KEY` | تشفير جلسات Flask | نعم، يتم توليده تلقائيًا |
| `DATABASE_URL` | رابط قاعدة البيانات | نعم، يتم ربطه تلقائيًا بـ PostgreSQL |

للتشغيل المحلي يمكن ترك المتغيرات بدون إعداد، وسيستخدم التطبيق SQLite في ملف `restaurant.db`.

## ملاحظات أمنية

- غيّر `SECRET_KEY` في الإنتاج ولا تضع مفتاحًا سريًا داخل الكود.
- غيّر كلمة مرور المستخدم `admin` فورًا.
- لا ترفع ملفات قواعد البيانات أو كلمات المرور إلى GitHub.
- استخدم متغيرات بيئية للبيانات الحساسة.
- خذ نسخًا احتياطية منتظمة من قاعدة PostgreSQL.
